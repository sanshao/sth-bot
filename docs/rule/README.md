## 运行方式

在仓库根目录执行（脚本以当前工作目录拼接路径）：

```bash
source .venv/bin/activate
pip install -r requirements.txt   # 首次运行
python src/run.py
```

- 输入目录：`src/run.py` 中的 `target_directory`，当前为 `resource/2026/支付宝-10月`，换月份时修改此处。
- 文件分发：按上表从上到下判断文件名，命中即交给对应模块，**先判断 `聚合`、`淘宝买菜`、`淘工厂`，再判断 `淘宝`**，因此 `淘宝买菜…` 不会被当作淘宝店处理。只处理 `.xlsx`，其它文件忽略。
- 输出目录：`output/整理/YYYYMMDD_HHMMSS/`，每个文件输出为 `<原文件名>_整理.xlsx`，包含两个工作表：
  - `整理`：原始流水加上 `净值`、`分类`、`税率` 等列。
  - `透视`：按分类汇总 `净值`（京东为 `金额`）与 `行数`，末尾追加 `总和` 行。

## 支付宝账单通用流程

淘宝店、淘工厂店、天猫店、淘宝买菜四类都是支付宝账单，流程相同：

1. 读取第一个工作表，以第 5 行为表头，跳过末尾 4 行汇总。
2. 清理列名两侧空格。
3. `备注` 为空（含空白/制表符）时，用 `商品名称` 填充 `备注`（平台常把在线支付等流水的说明写在商品名称里），之后的规则匹配和输出都使用填充后的备注。
4. 新增 `净值 = 收入金额（+元） + 支出金额（-元）`。
5. 按规则匹配 `分类`，按商品名称计算 `税率`。
6. 把 `净值` 移到 `支出金额（-元）` 与 `账户余额（元）` 之间。
7. 生成透视表。

分类命名约定：

| 账单 | 分类前缀 | 不允许出现的前缀 |
| --- | --- | --- |
| 淘宝买菜 | `淘宝买菜-`（如 `淘宝买菜-交易收款`、`淘宝买菜-提现`） | `淘菜菜-`、`淘工厂-`、`淘宝-` |
| 淘工厂店 | `淘工厂-`（如 `淘工厂-交易收款`、`淘工厂-提现`） | `淘菜菜-`、`淘宝-` |

只有按对方账户区分的分类（个人转账、网商贷、花呗还款、门道商家助手等）保持原名。

聚合、京东、拼多多的读取方式和金额计算不同，见各自文档。

## 规则引擎

实现位于 `src/category_rules.py`，规则文件是一个有序数组：

```json
[
  {
    "category": "淘工厂-淘客佣金",
    "condition": { "field": "备注", "op": "contains", "value": "C2M-正向扣佣-精选淘客" }
  },
  {
    "category": "淘工厂-交易收款",
    "conditions": [
      { "field": "备注", "op": "contains", "value": "C2M订单交易货款分账" },
      { "field": "备注", "op": "contains", "value": "订单交易货款分账" }
    ]
  }
]
```

### 匹配规则

- **从上到下匹配，第一条命中的规则决定分类**；全部未命中时为 `其它-未分类`（拼多多 `pdd1.py` 例外，未命中时使用原始 `业务描述`）。
- `condition`：单个条件。
- `conditions`：条件数组，**任意一个命中即可**（或关系）。
- 条件内部可嵌套组合：

| 写法 | 含义 |
| --- | --- |
| `{"all": [A, B]}` | A 且 B |
| `{"any": [A, B]}` | A 或 B |
| `{"not": A}` | 不满足 A |

### 支持的操作符

| 操作符 | 含义 | 说明 |
| --- | --- | --- |
| `contains` | 包含 | 子串匹配 |
| `startswith` / `endswith` | 开头为 / 结尾为 | |
| `eq`、`=`、`==` | 等于 | 两边都是数字时按数值比较，否则去掉首尾空格后比较文本 |
| `ne`、`!=` | 不等于 | |
| `>`、`>=`、`<`、`<=` | 数值比较 | 任一边无法转成数字时视为不命中 |
| `in` / `not_in` | 属于 / 不属于 | `value` 为数组 |

空单元格视为空字符串。

## 税率与透视细分

`税率` 列根据 `商品名称` 判定，只对分类名包含 `交易收款`、`限时红包` 或 `多买多省` 的流水生效，先判断 13% 再判断 9%：

| 税率 | 商品名称包含任一关键字 |
| --- | --- |
| 13% | 米布丁、酸奶、发酵乳、发酵奶、巧克力奶、藜麦牛奶燕麦、试乳牛乳饮品、牛乳饮品、牛乳茶乳饮料、原味蜂蜜0蔗糖、牛奶布丁 |
| 9% | 鲜奶、鲜牛乳、鲜牛奶、乳糖牛奶 |
| 空 | 其它情况 |

透视表中，分类名包含 `交易收款`、`限时红包` 或 `消费券` 且税率非空的流水，会拆成带税率后缀的分类，例如 `淘宝-交易收款9%`、`天猫-交易收款13%`。由于税率只对前述三类计算，实际只有 **交易收款** 和 **限时红包** 会出现后缀（`pdd1.py` 的细分对象为交易收款、限时红包、多买多省）。

## 维护规则

1. 修改对应的 `src/rules/<platform>_rules.json`。新规则如果比已有规则更具体（关键字包含已有关键字），必须放在已有规则**之前**。
2. JSON 由 Python `json.load` 严格解析，**不允许尾随逗号**和注释。
3. 用样例备注验证匹配结果：

   ```bash
   python -c "
   import json, sys, pandas as pd
   sys.path.insert(0, 'src')
   from category_rules import assign_category_by_rules
   rules = json.load(open('src/rules/taobao_factory_rules.json'))
   print(assign_category_by_rules(pd.Series({'备注': '扣款用途：C2M-正向扣佣-精选淘客-123'}), rules))
   "
   ```

4. 重新生成文档：`python docs/gen_rule_docs.py`。脚本会同时更新 skill 的参考文档，并在各平台文档末尾列出因顺序问题永远不会命中的条件。
